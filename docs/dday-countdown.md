# D-day 카운트다운 (#180)

2026-09-22 사용자 기획 승인으로 타이머 메뉴에 D-day 모드를 추가했다.
승인 범위는 기존 D-day 선택·관리 재사용, 밀리초 표시, 현지 날짜 00:00 도달,
관련 검증과 커밋·푸시·PR 생성이다. DB와 API 계약은 변경하지 않는다.

## 동작과 구현 근거

기존 D-day는 날짜만 저장한다. parseISO로 기기 현지 날짜의 시작 시각을 구하고,
목표 epoch에서 Date.now()를 빼 일·시·분·초·밀리초 3자리로 표시한다.
일은 남은 24시간 단위다. 목표 날짜 00:00에 도달한 날짜와 과거 날짜는 0으로 표시한다.

requestAnimationFrame으로 브라우저 화면 갱신에 맞춰 표시한다. 밀리초 표시는
1ms마다 렌더링한다는 뜻이 아니며, 각 프레임에서 실제 남은 밀리초를 계산한다.
갱신은 숫자 표시 컴포넌트에 한정하고, 숨겨진 탭에서는 중지한다. 복귀 시 현재
시각으로 재계산하고, 모드 이탈·대상 변경·언마운트 시 예약과 리스너를 정리한다.
스크린리더가 매 프레임 숫자를 읽지 않도록 timer의 live 알림을 끄고 완료만 알린다.

모드는 기존 타이머 저장값에, 선택한 D-day ID는 별도 localStorage 키에 보존한다.
선택 대상이 삭제되면 조회 목록의 첫 대상으로 전환한다. 날짜 수정은 목표 시각을
다시 계산한다. 조회 실패는 빈 목록으로 표시하지 않고 재시도를 제공한다.
선택·저장·계산은 브라우저에서 하며 서버 분기에 클라이언트 시각을 사용하지 않는다.
기기 시각·시간대 변경에 영향을 받는 개인용 표시이며 서버 시각 동기화는 하지 않는다.

## 검증

- git diff --check
- pnpm lint
- pnpm build
- pnpm test:e2e e2e/timer.spec.ts e2e/dday.spec.ts

타이머 E2E는 기존 스톱워치 복원과 일반 타이머 완료, D-day 밀리초 변화,
선택·모드 복원, 현지 자정 도달과 0 유지, 모바일 가로폭, 조회 실패 재시도와
빈 목록 관리 진입을 확인한다. D-day E2E는 기존 관리 CRUD를 확인한다.
전체 E2E와 성능 측정은 공통 내비·인프라 변경이나 정량 목표가 없어 선택하지 않았다.

결과: diff 검사·lint·빌드 통과. 기존 관리 CRUD·스톱워치·일반 타이머 3개
시나리오 통과, 신규 D-day 2개 시나리오 통과(인증 setup 별도 통과).
초기 신규 테스트의 시계 pauseAt 기준과 재시도 버튼의 main 범위를 수정했다.
