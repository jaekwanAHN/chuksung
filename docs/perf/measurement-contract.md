# 성능 측정 실행 계약

성능 전후 비교는 **같은 코드 실행 위치·계정·데이터·측정 설정**을 사용했을 때만
성립한다. 이 문서는 #148에서 확인한 변경 전 문제와, 하네스가 집행하는 변경 후 계약을
기록한다.

## 변경 전

`3da7058` (2026-08-25) 기준.

| 항목 | 문서·도구의 동작 | 결과 |
|---|---|---|
| 실행 위치 | `AGENTS.md`는 기본 체크아웃 전용, `/work`는 구현 워크트리에서 수정 후 측정 | 수정 전·후 코드를 같은 흐름으로 잴 수 없음 |
| 계정 | 워크트리에서 `PERF_TEST_USER_*`를 제거한 뒤 `account.mjs`가 E2E 계정으로 폴백 | 기준선과 수정 후 데이터셋이 달라질 수 있음 |
| 직렬화 | 문서로만 한 번에 하나를 요구 | 두 세션이 원장·포트·계정을 동시에 사용할 수 있음 |
| 델타 | 계정·볼륨이 달라도 경고 뒤 색상 델타를 계속 생성 | 비교 불가능한 값을 개선·회귀로 오해할 수 있음 |

경고는 이미 잘못된 측정이 기록된 뒤에만 보였다. 특히 E2E 폴백은 명령을 성공시키므로
실행자가 계약 위반을 놓치기 쉬웠다.

## 변경 후

### 측정 대상은 현재 체크아웃이다

기본 체크아웃과 `pnpm wt:new`로 만든 작업 워크트리 어디서든 `pnpm perf`,
`pnpm perf:diagnose`, `pnpm perf:deploy`를 실행할 수 있다. 빌드·원장·스냅샷은
**명령을 실행한 체크아웃**에 속한다. 따라서 작업 브랜치의 수정 전·후 기록이 같은
PR에 남는다.

워크트리 `.env.local`에는 계속 `PERF_TEST_USER_*`를 복사하지 않는다. perf 스크립트만
실행 시 기본 체크아웃 `.env.local`에서 두 키를 읽는다. `SUPABASE_SERVICE_ROLE_KEY` 등
다른 비밀은 상속하지 않는다.

### 전용 계정이 없으면 시작하지 않는다

`PERF_TEST_USER_EMAIL`과 `PERF_TEST_USER_PASSWORD`가 모두 없으면 인증 전에 실패한다.
E2E 계정 폴백은 없다. 로컬 Lighthouse와 배포 TTFB 측정에 같은 규칙을 적용한다.

### 저장소 전체에서 한 번에 하나만 돈다

세 perf 명령은 기본 체크아웃의 `.claude/worktrees/.perf.lock`을 공유한다. 측정이 이미
진행 중이면 기다리며 자원을 점유하지 않고 주인 PID·시작 시각을 알린 뒤 실패한다.
프로세스가 비정상 종료해 남긴 잠금은 다음 실행이 회수한다.

git 인덱스를 보호하는 `.repo.lock`과는 별개다. perf는 수 분 걸리므로 같은 잠금을
사용하면 그동안 `wt:new`·`wt:rm`·프리플라이트까지 막게 된다. 단, 죽은 잠금 회수와
새 잠금 생성이 경합하지 않도록 **획득 판단 순간에만** `.repo.lock`을 빌린다.

### 비교 조건이 다르면 새 기준선이다

로컬 원장은 다음 중 하나라도 어긋나면 색상 델타를 만들지 않는다.

- 계정이 양쪽 모두 `perf`가 아님
- run 수, 폼팩터, throttling 설정이 다름
- 한쪽 데이터 볼륨을 읽지 못했거나 볼륨 드리프트 임계값을 넘음

배포 원장은 계정·대상 오리진·run 수·프록시 리전·대조군 상태를 확인한다. 비교할 수
없으면 이유를 경고하고 해당 회차를 새 기준선으로 기록한다. 과거 E2E 스냅샷은 읽을 수
있지만 새 측정의 비교 대상이 되지는 않는다.

## 작업 브랜치에서 전후 측정

성능 수치가 성공 기준인 작업에서만 수행한다.

1. 대상 확정 직후 만든 작업 워크트리에서 수정 전 `pnpm perf --page <경로>` 실행
2. 생성된 기준선 스냅샷과 원장 변경을 보존
3. 코드 수정·기능 검증
4. 같은 워크트리에서 **같은 명령과 데이터 조건**으로 수정 후 측정
5. 원장의 두 회차와 색상 델타를 함께 커밋

성능 수치가 성공 기준이 아닌 버그·구조·문서 작업에는 이 절차를 적용하지 않는다.

## 검증

- `account.test.mjs`: E2E 폴백 금지, 기본 체크아웃에서 두 perf 키만 상속
- `perf-lock.test.mjs`: 동시 실행 거부, 죽은 잠금 회수, 실패 후 잠금 해제
- `ledger.test.mjs`: 계정·볼륨·설정 불일치 시 델타 제거
- `deploy-ledger.test.mjs`: 배포 측정 조건 불일치 시 델타 제거
- `pnpm perf --help`, `pnpm perf:deploy --help`: 작업 워크트리에서 초기화 가능
- `pnpm test:unit && pnpm lint && pnpm build`: 스크립트와 앱의 기존 게이트

실제 Lighthouse 전후 수치는 앱 성능을 바꾸는 작업에서만 남긴다. 이 변경은 측정 대상의
렌더링 성능이 아니라 하네스 계약을 고치므로 원격 계정을 사용하는 실측을 성공 조건으로
삼지 않는다.

## 한계

- 원격 Supabase와 로컬 머신은 여전히 공유 자원이라 perf 자체는 병렬화하지 않는다.
- 배포 측정은 단일 지점·단일 회선의 TTFB이고 렌더링 지표를 보지 않는다.
- 기준선과 수정 후 사이에 perf 계정 데이터가 바뀌면 새 기준선 처리된다. 원인을 자동으로
  복구하거나 데이터를 되돌리지는 않는다.
