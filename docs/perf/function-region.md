# 함수 리전 (`vercel.json` → `icn1`)

## 결론

Vercel 함수를 서울(`icn1`)에서 실행한다. Supabase 프로젝트가 `ap-northeast-2`(서울)이고
주 사용자도 한국이므로, 함수를 둘 사이에 두는 것이 유일하게 합리적인 배치다.

```json
{ "regions": ["icn1"] }
```

## 왜 필요했나

Vercel 신규 프로젝트의 기본 함수 리전은 **`iad1`(워싱턴 D.C.)** 이다. 명시하지 않으면
그대로 적용되므로, 배포 이후 줄곧 아래 경로로 요청이 흘렀다.

```
서울 사용자 → icn1 엣지 → iad1 함수 → 서울 Supabase → iad1 → 서울
```

응답 헤더 `x-vercel-id: icn1::iad1::...` 이 이 경로를 그대로 드러낸다.
앞이 진입 엣지, 뒤가 함수 실행 리전이다.

비용은 두 겹으로 붙는다.

1. **사용자 ↔ 함수** — 모든 SSR 페이지·API 호출이 태평양을 왕복한다.
2. **함수 ↔ Supabase** — `supabase.auth.getUser()` 는 로컬 쿠키를 신뢰하지 않고
   매번 Auth 서버에 검증을 요청하는 함수다. 요청 하나에 여러 번 발생하고,
   각각이 태평양 왕복이었다.

특히 2번이 누적된다. 로그인 사용자가 `/` 로 진입할 때의 직렬 `getUser` 호출:

| 지점 | 파일 |
|---|---|
| 프록시 세션 갱신 | `src/lib/supabase/update-session.ts` |
| 루트 분기 | `src/app/page.tsx` |
| `/daily` 재요청 시 프록시 | (동일) |
| 대시보드 레이아웃 프리페치 | `src/app/(dashboard)/layout.tsx` |
| 각 Route Handler | `src/lib/api/route-helpers.ts` (`withAuth`) |

## 측정

`docs/perf/deploy-latency.md` 참조. 요약하면 인증 API 응답이 1초 안팎에서
100ms 대로 떨어졌고, 무료 플랜 여부와는 사실상 무관한 문제였다.

## 한계 / 알아둘 것

- **Hobby 플랜은 단일 리전만 가능하다.** 여러 리전 분산은 Pro(5개) 이상이다.
  지금은 사용자와 DB 가 모두 한국이라 단일 리전으로 충분하다.
- **Routing Middleware(`src/proxy.ts`)는 `regions` 설정을 따르지 않는다.**
  Vercel 은 미들웨어를 별도 정책으로 배치하며 Hobby 에서는 더 적은 리전에서 실행된다.
  따라서 이 설정만으로는 프록시의 왕복이 사라지지 않았다 — 프록시만 홀로 먼 곳에
  남았고, 그래서 프록시는 왕복 자체를 없애는 쪽(로컬 JWT 검증)으로 따로 처리했다.
  `docs/auth-redirects.md` 의 "프록시는 낙관적으로만 판단한다" 참조.
- **프록시 실행 리전은 응답 헤더 `x-proxy-region` 으로 관측한다.** `x-vercel-id` 는
  프록시가 끝낸 응답에서 진입 엣지만 남기고 실행 리전을 알려주지 않는다. 이 설정과
  프록시 배치가 어긋나도 빌드·테스트는 통과하므로, 관측 수단을 코드에 남겨둔다.
  **2026-08-11 실측값은 `sin1`(싱가포르)** — 함수는 `icn1`, 프록시는 `sin1` 로
  갈라져 있다. 프록시의 Auth 왕복은 #90 으로 없앴지만 **남은 지리적 지연(약 106ms)은
  코드로 줄일 수 없다.** Hobby 플랜에서는 미들웨어 배치를 지정할 수 없다.
- **Supabase 리전을 옮기면 이 설정도 같이 옮겨야 한다.** 두 값은 항상 같은 곳을
  가리켜야 하며, 어긋나도 빌드나 테스트는 통과한다. 조용히 느려질 뿐이다.
- **로컬 `pnpm perf` 는 이 문제를 구조적으로 감지하지 못한다.** 로컬 빌드를 로컬
  Chrome 으로 측정하므로 함수-DB 거리가 0 이다. 실제로 원장(`history.md`)에는
  `/daily` Perf 95 로 양호하게 기록돼 있었지만 배포 환경의 체감은 전혀 달랐다.
  배포 URL 기준 측정이 별도로 필요하다.
