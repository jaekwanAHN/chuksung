# 도구 환경변수 로딩 (#111)

## 결정과 범위

2026-09-16 사용자가 `.env.test` 지원 제거 계획을 승인했다. 승인 범위는 네 로더와
관련 안내 수정, 환경 로드 시나리오·관련 unit·lint·전체 E2E 검증, 커밋·푸시·PR 생성이다.
작업 기준은 `c105e2d`, 브랜치는 `fix/env-local-loading`이다.
같은 날 사용자의 이어서 진행 지시로 기존 워크트리를 인계받아 남은 검증과 PR 생성을 진행했다.

기존 네 로더는 `.env.local` 다음 `.env.test`를 읽었지만 `process.loadEnvFile`은
기존 키를 덮어쓰지 않는다. Node v24.18.0에서 같은 키에 `from_local`, `from_test`를
설정해 실행하면 `from_local`이 남는 것을 재현했다. Playwright의 우선순위 주석과
E2E README의 폴백 설명 모두 실제 동작과 달랐다.

워크트리 슬롯은 `.env.local`, CI는 job 환경변수로 주입한다. 별도 오버라이드 파일을
지원하는 대신 네 도구의 `.env.test` 로드를 제거했다. 기존 환경변수가 우선하고
`.env.local`은 없는 키만 채운다. 사용법·이전 안내의 원본은
[e2e/README.md](../e2e/README.md#환경변수-로드-계약)다.

perf 전용 계정 상속과 슬롯 주입 방식은 기존 규칙을 따른다. 이 결정은 네 도구의
명시적 로더에 한정한다. Next.js 자체는 `NODE_ENV`에 따른 환경 파일 로딩을 유지한다.

## 검증

- `git diff --check`: 통과.
- 네 로더의 실제 구문을 TypeScript AST로 추출해 별도 Node 프로세스와 임시 디렉터리에서
  실행했다. 각 로더에 다음 네 조건을 적용한 **16개 시나리오가 통과**했다.
  - 두 파일에 같은 키가 있으면 `.env.local` 값 사용, `.env.test` 전용 키 미반영.
  - 실행 환경에 같은 키가 있으면 실행 환경 값 유지.
  - `.env.test`만 있으면 해당 값을 읽지 않음.
  - 두 파일이 없으면 오류 없이 기존 환경 사용.
- `node --test scripts/perf/account.test.mjs`: 3개 통과. perf 계정 선택·기본 체크아웃 상속·
  불완전한 자격증명 쌍 처리의 기존 동작을 확인했다.
- `pnpm lint`: 통과.
- `pnpm test:e2e`: 전체 63개 통과 (1.8분). 워크트리 전용 포트 3102에서 실행했다.
  최초 샌드박스 실행은 개발 서버 시작 단계에서 종료됐으며, 실행 권한 승인 후 재실행해 통과했다.
- 로드 코드와 안내를 검색해 네 도구의 `.env.test` 로드가 남아 있지 않음을 확인했다.

임시 시나리오는 각 로더의 파일 선택·우선순위를 직접 확인하며 계정 프로비저닝이나
GUI 로그인을 실행하지 않는다. 공통 E2E 설정 변경은 전체 E2E로 검증한다.
앱·빌드 설정과 워크트리 스크립트는 바뀌지 않으므로 빌드·전체 unit·성능 측정은
선택하지 않았다. 새 회귀 테스트 파일 대신 위 실행 증거와 기존 관련 unit을 사용했다.
